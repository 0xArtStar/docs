## Overview

The wallet is the user's on-chain identity entrance in ArtStar, and it is also the foundation for subsequent login, KYC, authorization, subscription, and position display. The network determines whether these interactions occur in the correct chain environment.

Therefore, wallet connection and network switching are not simply technical prerequisites, but the first threshold determining whether a user can smoothly participate in the platform. If the wallet status is unstable, all subsequent processes will be affected.

## Access Mechanism and Functions

<AccordionGroup>
  <Accordion title="Why is wallet access important?" icon="wallet">
    In ArtStar, the wallet assumes at least the following roles:
    * Identifies the user's on-chain address
    * Coordinates with signatures to complete login authentication
    * Queries stablecoin balances and authorization status
    * Initiates on-chain transactions (Approve / Mint)
    * Displays user positions and asset records
  </Accordion>
  <Accordion title="Network Guard Mechanism" icon="shield">
    ArtStar's core interactions run on a designated chain. To prevent users from staying on the wrong network resulting in asset reading errors or transaction failures, the frontend usually needs the following capabilities:
    * Detect the current Chain ID and determine if it's the target chain
    * **Block critical write operations** when on the wrong chain
    * Guide users to switch networks with one click
    * Automatically restore the interaction flow after a successful switch
  </Accordion>
</AccordionGroup>

## Basic Access Flow

From a product perspective, the goal of this step is not "connecting the wallet" itself, but allowing the platform to identify and serve the current user:

<Steps>
  <Step title="Connect Wallet">The user clicks connect wallet, invoking the wallet extension or app.</Step>
  <Step title="Get Address">The wallet authorizes the connection and returns the current address.</Step>
  <Step title="Status Initialization">The frontend initializes UI states related to that address.</Step>
  <Step title="Signature Login">If necessary, guide the user to complete signature verification to establish a backend session.</Step>
  <Step title="Data Reading">The frontend continues to read balance, network, and permission-related information, entering the main business flow.</Step>
</Steps>

## Common Exceptions and Troubleshooting

Users may encounter the following issues during the wallet connection and network switching phases. The frontend needs to provide clear, actionable prompts rather than just generic error messages:

<Card title="Common Errors" icon="bug">
  * Wallet extension not installed or not invoked
  * Wallet connection request rejected by the user
  * Address reading failed
  * Current network error (not on the target network like BNB Chain)
  * Automatic switch request unresponsive
  * Compatibility issues with built-in browsers in mobile wallets
</Card>

## Pitfall Guide

<Callout type="warning" title="Connecting the wallet ≠ Completing login">
  Connecting the wallet only gets the address. If the platform also requires signature-based backend sessions, the user might still be in a "connected but not logged in" state, requiring explicit frontend guidance.
</Callout>

<Callout type="danger" title="Automatic network switching is not always successful">
  Some wallets, browsers, or mobile environments do not support stable automatic switching, so you cannot assume it will always succeed after calling the switch method once. A post-check based on the actual Chain ID is required.
</Callout>

<Callout type="info" title="Synchronously clear status after wallet disconnection">
  When the user actively disconnects the wallet, the platform should synchronously clear the page status, cached data, and session information dependent on that address to avoid anomalies caused by residual old data.
</Callout>
